# Mira Studio

Mira turns an uploaded image into a reviewed shot plan and real Wan 2.2 I2V video. The web app handles image understanding and the director workflow; every video segment is generated by the separately hosted dedicated Wan 2.2 GPU API. Multi-segment films are stitched by that API into an MP4.

## Run the web app

Requires Node.js 22. Install dependencies, then start Vite:

```powershell
npm install
npm run dev
```

To deploy the UI to Vercel, import this folder/repository; `vercel.json` sets the Vite build and output directory. After deployment, open GPU settings and enter your GPU API's public HTTPS URL and API key. Hosted Mira no longer defaults to `localhost`, because that address would point at each visitor's own device.

## Image privacy

When you choose **Study image & build director plan**, Mira sends a resized image to the public Hugging Face Space `developer0hye/Qwen2.5-VL-7B-Instruct` for scene analysis. Do not upload images you are not comfortable sending to that service. Video generation requests go to the dedicated GPU URL you configure in the app.

## Dedicated Wan 2.2 GPU service

The `mira-wan-gpu/` folder contains the FastAPI service and Docker configuration. It requires a Linux NVIDIA host, CUDA-compatible drivers and container runtime, FFmpeg, storage for model weights and outputs, and Wan 2.2 I2V A14B weights. The service defaults to requiring 80 GB of VRAM; the published single-GPU setup is documented by the [official Wan 2.2 repository](https://github.com/Wan-Video/Wan2.2). Vercel hosts only the UI and does not run inference.

1. In `mira-wan-gpu`, copy `.env.example` to `.env`.
2. Set a long `MIRA_API_KEY` and the exact production `MIRA_FRONTEND_ORIGIN`.
3. Start the service with `docker compose up --build -d`.
4. In Mira's GPU settings, enter the public HTTPS GPU URL and matching API key.
5. Run the service's real `/self-test` endpoint before production use.

Use the public HTTPS API URL when the web app is deployed. `localhost` on a visitor's browser refers to that visitor's computer.

## Notes

- The **Professional** preset sends 40 inference steps to Wan 2.2; **Fast draft** sends 8. The model card's Diffusers example uses 40 steps, which is a strong starting point for final renders but takes longer and uses more GPU time.
- Mira has no video-generation fallback. If the Wan API is unavailable, generation stops with an error.
- Mira assembles generated segments into an MP4 on the GPU service. Segment durations follow the backend's supported frame/fps combinations, so total runtime is approximate.
- The service must allow the exact Vercel origin through CORS and must be configured with the same API key entered in the web app.
- No GPU hardware, hosted service, API secret, or model weights are included in this source bundle.
